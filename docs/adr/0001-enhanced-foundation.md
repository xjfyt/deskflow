# Deskflow Enhanced 技术决策

## 上游与模块边界

采用官方 Deskflow `master` 作为长期基线。增强库复用仓库的 Qt、OpenSSL、证书生成和构建方式，经典模块维持其协议与队列。当前源码与许可来源见 [P0 基线](../../P0_BASELINE.md)。

## 传输与授权

增强通道固定使用 TLS 1.3。两端传入对方已核对的 SHA-256 叶证书指纹，并发送本端证书。指纹匹配、证书有效期和 TLS 持钥证明是接受增强消息的前提。监听地址和执行一次接收是本端授权，关闭会话或更换指纹撤销该次授权。身份文件、增强授权和经典的可信指纹数据库各自独立。每次连接禁用 TLS 会话复用。

文件控制和数据用不同 TCP 连接。数据端重复认证为同一个已授权设备，验证 32 字节的随机一次性令牌，令牌有效期为 15 秒。授权对应当次控制连接、清单和已选择的接收目录。连接未通过认证时可在监听期限内重新尝试，数据通道在等待时检查控制连接。最终提交前再次等待控制连接上的完成确认。单次接收可等待两分钟，每个数据帧有收发超时，整个传输上限为四小时。文件提交后若回执丢失，发送端提示核对收件目录再重试。

## DFEX 1.0 帧

每帧头为 24 字节，数值使用网络字节序。

| 字段 | 宽度 | 约束 |
| --- | --- | --- |
| magic | 4 字节 | ASCII `DFEX` |
| major / minor | 各 2 字节 | 发送 1.0，主版本必须一致 |
| type / flags | 各 2 字节 | 消息类型由状态决定，保留标志位必须为零 |
| payload size | 4 字节 | 至多 256 KiB，具体消息另有限额 |
| sequence | 8 字节 | 自 1 起，按传输方向递增，拒绝跳号和重放 |

文件控制流为 `HELLO → OFFER → ACCEPT → FINISH → COMMITTED`。双方交换能力位，文件能力为 0x01。清单编码为 32 位条目数，每个条目含 8 位类型、64 位大小、16 位 UTF-8 路径字节数与路径。目录在子项前，清单不携带发送端绝对路径。文件数据流为 `DATA_OPEN → DATA_READY → [CHUNK… → DIGEST → FILE_ACK]… → FINISH`。清单内顺序决定当前条目，块长精确匹配文件剩余大小和 64 KiB 块大小。摘要固定为 32 字节 SHA-256。

双方都启用续传后使用能力位 0x04，在一个普通文件的 OFFER 和 ACCEPT 之间交换源版本与全文件摘要、对齐到块的偏移与前缀摘要，以及验证确认。检查点绑定双方证书并受目标目录锁保护。拖放能力位 0x08 用于明确同意暂存式交接，文件内容仍按普通文件流程传输。双方只使用已启用的能力。

Windows 输入使用独立连接，HELLO 的能力和租约版本字节为 `02 02`。双方轮询交换 `INPUT_POLL` 与 `INPUT_STATE`，每包最多 64 个输入事件，事件含种类与两个 16 位参数。监听端为每次申请分配递增 epoch，先发待生效租约，目标侧回复就绪后才允许来源捕获并转发物理事件。待生效和活跃租约均有超时。接收侧验证 epoch 和按键状态，播放队列有界。目标侧本机输入可释放当前租约，断线或看门狗超时释放已注入的按键与按钮。恢复后建立全新会话。双机输入双方须使用支持新版租约的构建，文件通道仍使用 1.0。

X11 与 macOS 复用会话与租约逻辑，分别使用 `02 03` 与 `02 04`。平台原生键码目前由同族对端解码。异族能力在进入物理输入控制前拒绝。设备路由模型由已认证标识限制来源、落点和释放权限，现有传输承担两个设备。

## Windows 输入后端

双机使用 Windows 低层键鼠 hook 和带标记的 `SendInput`。连接角色用于监听与仲裁，两端都可发起控制。运行前取得增强模式锁和经典 core 的实例锁。GUI 通过本机子进程 stdin 请求协作停止，通过 stdout 显示状态，关闭管道也会触发退出。物理事件和带 Windows injected 标志的事件在 hook 中区分。布局变化释放当前租约，安全桌面切换结束会话。Windows 可以阻止安全桌面和 UIPI 边界上的注入，失败会记录。

## 文件、剪贴板和拖拽

源端通过交互进程读取本次选中的文件，目标端先验证清单，再在所选接收目录下建立独立暂存树。跨平台路径规则拒绝设备名、相对穿越、流后缀和大小写重复。源文件在受控打开时拒绝链接及非普通文件，Windows 下逐层检查重解析点。默认单批次上限 20 GiB、4096 项、256 KiB 清单。目标先写入全新文件，校验摘要后一次公布完整目录，使用独立批次名避免覆盖。

文件剪贴板把本地收件路径发布为系统文件 URL，并提供 Windows、GNOME 或 KDE 的复制格式。文件选区里的剪切标记统一按复制处理。缓存使用用户选定的接收目录，剪贴板在传输期间改变时保留其最新内容。当前拖放可向源端传输窗口放入文件，也可从目标端的已收列表发起本机复制式拖放。跨屏释放与 Finder、Explorer 的原生目标投递需要后续 OS 适配，Wayland 可通过文件窗口选择和收件目录完成交付。
