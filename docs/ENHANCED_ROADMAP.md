# Deskflow Enhanced 后续开发与验收

每个阶段先交付一个可独立启用的能力，再扩展到下一阶段。真实桌面的输入权限、拖放落点和按键释放分别验收。跨平台构建和包检查由 [发布工作流](RELEASES.md) 记录。

| 阶段 | 本轮交付 | 下一阶段的验收门槛 |
| --- | --- | --- |
| 1. 双向输入后端 | 提取共用的认证、心跳、锁和两阶段租约。保留 Windows 后端，新增受 Xorg、XI2/XTEST 与登录会话约束的 X11 入口，以及受系统授权约束的 macOS 入口 | 分别完成 Windows↔Windows、X11↔X11、macOS↔macOS 的越界、返回、按键和断网验证。验证目标接受前源端仍可用，断线能释放目标端已注入的键和按钮 |
| 2. 跨系统输入 | 各后端声明本机按键协议族，同族协商通过后才进入会话 | 引入平台无关的物理键表示，补 Win 扫描码、macOS 虚拟键码、XKB 和布局测试。完成 Win↔Mac、Win↔X11 双向验收后，才公布跨系统支持。Wayland 另走授权的 Portal/libei 方案 |
| 3. 三机路由 | 带设备标识的路由租约仲裁已接入双机会话，新增三设备的授权、竞争、就绪、输入归属和断开用例 | 新建 hub 网络模式，分别认证每个对端，依据已确认的屏幕边归属选择目标。源端、目标端和 hub 任一方断开均释放租约。最后实测 A↔B、B↔C 和 A→C，明确多设备显示器与布局权限 |
| 4. 原生跨屏拖拽 | 双端可启用一次暂存式交接。源端把选区拖入 Deskflow，目标端文件校验完成后使用本机原生拖放落到文件管理器 | 在 Windows OLE 与 macOS AppKit 分别验证可授权的原生源和目标会话。协商必须由明确的源用户手势和目标落点驱动，保留取消与复制语义。第三方应用的全局实时跨屏接管、Finder/Explorer 双向落点和 Wayland 降级分别验收 |
| 5. 文件续传 | 命令行双端可为单个普通文件启用续传。对端指纹、源文件版本和全文件 SHA-256 绑定检查点，双端复核保留前缀，完成后才原子公布 | 覆盖进程重启、中断、接收端空间不足、篡改和源文件变化。随后扩展到多文件和目录、GUI 恢复授权、配额与可控清理 |

## 三机控制协议边界

Hub 将已认证证书指纹映射到会话内设备编号，编号由 Hub 分配。路由由接入时确认的布局和对端授权决定。Hub 对每次路由分配新的 epoch，目标应答就绪后才开始发送，只有当前来源的输入可以发给目标。任一相邻屏幕从活动列表移除时，先释放旧路由，再处理下一次申请。每条设备连接有独立的队列、截止时间和证书校验。文件数据继续在两端独立连接。

现有设备编号仲裁只接受允许的有向边。测试用 A↔B↔C 布局覆盖 C 无法结束 A→B，B→C 需要 C 就绪，两端并发申请不会获得多个路由。网络层当前仍是两台设备，三台设备不能通过现有连接参数启用 hub。

## 原生拖放边界

Windows OLE `DoDragDrop` 使用参与本机拖放的源与目标接口，macOS AppKit 使用本机事件启动 `NSDraggingSession`。应先在 Deskflow 自己的窗口验证交接和落点，再研究可明确授权的第三方选区。当前方案交给平台的仅是接收后真实存在的文件，目标机发起本机复制式拖放，源文件和剪贴板得到保留。 [Windows OLE 文档](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-dodragdrop) · [AppKit 拖放会话](https://developer.apple.com/documentation/appkit/nsview/begindraggingsession(with:event:source:))

## 复验优先级

1. 同版本 Windows 双机先完成物理输入与经典回退，然后补 X11 和 macOS 同系统测试。
2. 文件原样、拖放落点和双机剪贴板行为用 [验收矩阵](ENHANCED_AUDIT.md) 逐项验证。
3. 在测试目录以超过数个 64 KiB 块的文件验证中断后的非零续传偏移，复核最终 SHA-256。测试源内容变化、检查点损坏、错误指纹和显式清理。
