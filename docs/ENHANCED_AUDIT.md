# Deskflow Enhanced 实施复核与验收矩阵

复核日期为 2026-11-24。官方基线为 `80221f0f7b7ebd807fb1ffdf00906bbcfe561011`。增强分支 `deskflow` 发布于公开仓库。上游同步与回归入口见 [维护说明](UPSTREAM_SYNC.md)。

## 原方案复核

| 原计划 | 本轮落地 | 验收或开发缺口 |
| --- | --- | --- |
| P0 基线 | 核对官方 HEAD，新建私有仓库与 `deskflow` 分支 | 经典双机输入、TLS 和普通剪贴板待实机验收 |
| P1 文件协议 | 保持文件线协议，校验源目录和文件身份与版本，等待通过指纹认证的对端，数据通道检查控制连接，区分最终提交回执丢失 | 双台主机 1 GiB 与并行输入延迟待测 |
| P2 双向输入 | Windows 双机增加待生效租约、目标就绪确认、交互桌面限制、断线释放、互斥、防回环与 GUI 状态 | 两端须更新到新版。物理挂钩、返回边缘、屏幕布局变化和断网重复验收待测 |
| P3 文件剪贴板 | 支持标准文件 URI 和 GNOME 文件列表，识别 Windows、GNOME 和 KDE 剪切标记并按复制发送，抑制本地路径的纯文本回退 | Explorer、Finder、GNOME、KDE 的热键和右键粘贴需要组合验收 |
| P4 拖放 | 已校验收件可由目标机窗口复制式拖入本机文件管理器 | 源应用原生拖拽捕获、跨屏交接、Windows OLE 与 macOS AppKit 落到原生应用待开发 |
| P5 Linux | 提供本机 URI 剪贴板和收件目录，增加独立 Linux 构建入口 | Wayland 剪贴板取决于合成器授权，XDND、Wayland 原生跨屏拖放及 Linux 双向输入后端待开发 |
| P6 设备与恢复 | Windows GUI 显示输入所有者，可选择保存一组成功验证的对端配置，随时停止会话。失败批次清理，已提交批次可在收件目录复核 | 三机路由、完整设备列表和发现、按设备细分权限、自动缓存配额与断点续传待开发 |
| P7 验证与发行 | Windows 本地编译、手动跨平台构建工作流、边界与回环用例、可选 Clang 解码 fuzz 目标 | 跨平台构建结果、fuzz 执行、签名、覆盖矩阵和延迟指标待记录 |
| P8 上游维护 | 官方与个人远程分开，记录同步和兼容回归步骤 | 后续随上游提交逐批执行 |

## 重点回归

| 编号 | 验收动作 | 通过条件 |
| --- | --- | --- |
| C01 | 新旧组合用经典 TLS 互联，移动鼠标，发送文本、HTML 和图片，两端互换 | 经典控制及剪贴板可用，两种配置均无输入冲突 |
| F01 | 分别以错误发送端指纹、错误接收端指纹开始传输 | 两端拒绝会话，收件目录没有本次完整或不完整文件 |
| F02 | 使用两端正确指纹发送 Unicode 名称、普通文件、空文件、空目录和 1 GiB 文件 | 清单与 SHA-256 一致，源文件保留，接收目录一次公布 |
| F03 | 在接收中修改或同大小替换源文件，单独重做取消和断网 | 本批次报失败或取消，无完整目标目录，临时数据被清理 |
| F04 | 接收期间将目标剪贴板改为文本，另用文件管理器剪切选区进行发送 | 文本保留，剪切项按复制发送，源路径不会经经典文本同步发出 |
| F05 | 在 Win↔Win、Win↔Mac、Mac↔Mac、Linux↔Win 分别复制、粘贴、拖放收到的文件 | 记录实际保存目录与是否支持本机复制式拖放 |
| I01 | 两台新版 Windows 依次用本机实体键鼠越过相邻边缘并返回，各成功 10 次 | 状态正确，能在同一配对连接中由任一端发起和退出 |
| I02 | 控制时目标端按键、滚轮或移动物理鼠标，另测试热键、退出 GUI、断网、锁屏和屏幕拔插 | 本机可抢回，断线和退出时无卡键。记录安全桌面释放异常 |
| I03 | 两端同时越界，目标端按住键再申请，尝试额外启动经典实例 | 同时只有一个生效租约；未就绪时源端不会开始捕获；两种输入模式互斥 |
| I04 | 重新打开 GUI，核对记住对端，取消勾选后再打开 | 保存配置填充表单，仍由用户启动；忘记后清空已保存的指纹 |
| I05 | 同时进行 1 GiB 传输与输入操作，比较空载和满负载 | 记录 p50、p95、p99 和本机接管时间，确认无丢键或卡键 |

验收记录需要两端硬件和系统桌面版本、构建 SHA、测试方向、屏幕布局、操作步骤以及 `PASS` / `FAIL` / `NOT TESTED`。粘贴和拖放记录文件最终位置与 SHA-256，输入恢复记录耗时。日志仅保留脱敏信息。

## 构建与回退

- **Actions → Enhanced packages** 支持标签触发和手动打包，覆盖 Windows、macOS 和 Debian 的 x64/ARM64 对应 runner。远程打包和实机结果需分别记录。 [打包与发布说明](RELEASES.md)
- 可在 Linux/macOS 使用 Clang 配置 `-DBUILD_ENHANCED=ON -DBUILD_TESTS=ON -DENABLE_ENHANCED_FUZZ=ON -DSKIP_BUILD_TESTS=ON`，然后构建 `EnhancedDecoderFuzz`。执行 `EnhancedDecoderFuzz -max_len=262145 -max_total_time=60` 可覆盖协议帧、文件清单及两种租约数据解码。
- 出现兼容问题时，通过窗口 **停止** 或热键退出增强输入，再启动经典 core。发版回退使用 `-DBUILD_ENHANCED=OFF`。文件接收保存在用户选择的本机目录。
