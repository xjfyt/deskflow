### Windows UAC 与本机文件粘贴

1. **经典模式与普通进程**。Windows B 作为客户端，先使用普通用户进程和默认 UAC 配置。从 A 越界控制 B，在 B 的开始菜单右键选择以管理员身份运行终端。弹窗出现后用 B 的实体鼠标移动并点击 **否**。回到普通桌面后再用 A 的共享鼠标在 B 上移动、点击，并尝试越界返回 A。再用 B 的实体设备触发一次，并以鼠标移回 A 后的状态分别复验。记录本机鼠标是否可用、共享输入恢复是否需要越界或重新连接。
2. **经典模式与系统服务**。若实际使用 MSI 的后台服务，在 Windows 客户端检查 **使用后台服务** 和 **始终以系统身份运行** 已启用，重启 classic core 后重做上项。分别记录 UAC 中共享鼠标与实体鼠标的表现。便携版或未启用系统服务的普通进程由本机设备处理受保护的提示。
3. **增强输入**。停止 classic core 后启动两端增强输入。A 控制 B 时触发 B 的 UAC，用 B 的实体鼠标处理提示，确认增强会话停止。回到桌面后在普通应用中确认没有卡住的 Ctrl、Shift 或鼠标按钮，然后重新启动增强会话并复测。可在 B 使用延时触发提升的测试程序，再由 A 按住 Shift，待弹窗出现后松开，以验证返回普通桌面后的释放。
4. **本机粘贴与跨机传输**。用经典模式连接两台 Windows。B 在资源管理器复制一个测试文件，A 的鼠标移回 A，在 A 复制一段文本再移回 B。在 B 的另一目录用 Ctrl+V 和右键菜单分别粘贴，确认文件存在且内容一致。另测试支持文件粘贴的应用，并用可丢弃样例测 Ctrl+X 后在本机目录移动。随后从 B 按增强文件窗口的 **发送下次文件复制** 发送文件给 A，A 校验收到后使用 **复制收到的文件** 本机粘贴，同时确认 B 仍可粘贴同一个源文件。最后在 B 复制新的普通文本再切到 A，确认文本共享恢复。

### Windows 文件剪贴板实机验收

1. 两台电脑都使用本次增强构建，保持原有服务器和客户端角色。核对主界面已经连接。使用普通的键鼠共享入口，用一段短文本确认两端剪贴板共享可用。
2. A 在资源管理器中同时选中一个中文名文件和一个含空目录的文件夹，按 `Ctrl+C`。移到 B 的另一个资源管理器文件夹，待收件就绪后按 `Ctrl+V`。将两端角色保留并换方向复测。对比文件名、目录层级和 SHA-256。在源电脑另一个文件夹粘贴同一个选区，确认源端仍能本机粘贴。
3. 复制测试用大文件，目标端在接收结束前用本机键盘复制一段文本。目标端粘贴应得到后来复制的内容。重新复制文件并等待就绪，目标端应可粘贴文件。测试断网重连后重新复制，以及快速连续复制两个不同文件。
4. 重做以上步骤，一端或两端改用 MSI 安装的后台服务并选择以系统身份运行。测试锁屏和解锁，再复制新文件。主界面若提示当前会话无法使用文件剪贴板，记录出现时的连接角色和运行身份。
5. 使用 `0.1.0` 当一端，或在当前服务器上连接第二个客户端。检查普通文本和键鼠共享仍可用。第三台退出后，从新版双方分别重新复制测试文件，检查文件剪贴板恢复。
6. 复制 1 GiB 样例时，在两端持续移动共享鼠标并输入文字。记录与空载时相比是否有停顿和卡键，随后校验样例 SHA-256。

### 续传实机验收

两台机器使用本轮同一构建。按 [独立文件传输窗口](Enhanced.md#独立文件传输窗口) 填写对端指纹和地址。接收端准备空的测试目录，可用空间应大于样例大小。Windows 可以生成一个 2 GiB 样例并记下发送端的 SHA-256。

```powershell
$source = Join-Path $env:TEMP 'deskflow-resume-test.bin'
$stream = [IO.File]::Open($source, [IO.FileMode]::CreateNew)
try { $stream.SetLength(2GB) } finally { $stream.Dispose() }
Get-FileHash -LiteralPath $source -Algorithm SHA256
```

1. **中断和恢复**。两端开启续传。接收端选择空目录并等待，发送端只发送样例。看到数据进度后、完成前，接收端点击 **取消**。等待两端退出。接收目录应有隐藏的 `.deskflow-resume-v1`，没有新 `Deskflow-<UUID>`。如果局域网较快，换用更大的样例后重做。
2. **重启和完整性**。关闭并重开两端应用，重新核对指纹、勾选续传。B 用同一接收目录监听，A 发送原路径中未改动的样例，两次之间在 24 小时内。两端应显示同一个大于 0 的恢复字节数，接收端仅新建一个完整批次，检查点消失。对实际收件文件运行 `Get-FileHash -LiteralPath '实际收件文件完整路径' -Algorithm SHA256`，结果应与源相同。
3. **拒绝不一致**。用新空目录分两次重做中断。第一次只在一端勾选续传后重试，应提示两端都要开启，原检查点仍在。第二次在两端空闲时，用测试样例对检查点的 `files/deskflow-resume-test.bin` 原地改动首个字节并保留文件长度。两端都勾选后续传应拒绝校验，接收端不会公布新批次。也可在中断后修改源文件，验证检查点与源版本不匹配。
4. **清理与重新开始**。结束传输，在接收端选择 **清除续传检查点…** 并指向原接收目录。先选 **否** 确认进度还在，再选 **是** 确认检查点消失。目录里的已完成批次应保留。再清同一目录应提示没有检查点。用正常源文件重新传输应从零开始并完成。
5. **空间不足**。在可用空间小于样例、当前无检查点的测试卷重复首传。接收端应报告空间不足，目录内无新检查点。也可在中断后保留检查点，将测试卷的剩余空间降到待传字节数以下再重试。此时接收端应拒绝续传，并保留原进度供腾出空间后重试。

拖放、输入和三机中继按 [各平台启动方法](Enhanced.md) 配置，再执行上表 F07、I01–I08。测试中继时按 H、A、B 的顺序启动，记录 A→B 和 B→A 的结果，重连后再从另一侧复测断线释放。

## 构建与回退

- **Actions → Enhanced packages** 支持标签触发和手动打包，覆盖 Windows、macOS 和 Debian 的 x64/ARM64 对应 runner。远程打包和实机结果需分别记录。 [打包与发布说明](RELEASES.md)
- 可在 Linux/macOS 使用 Clang 配置 `-DBUILD_ENHANCED=ON -DBUILD_TESTS=ON -DENABLE_ENHANCED_FUZZ=ON -DSKIP_BUILD_TESTS=ON`，然后构建 `EnhancedDecoderFuzz`。执行 `EnhancedDecoderFuzz -max_len=262145 -max_total_time=60` 可覆盖协议帧、文件清单及两种租约数据解码。
- 出现兼容问题时，通过窗口 **停止** 或热键退出增强输入，再启动经典 core。发版回退使用 `-DBUILD_ENHANCED=OFF`。文件接收保存在用户选择的本机目录。
